# 13 · 问数客户端与语义层后台的界面产品化设计

> 与 [11 产品功能设计](11-产品功能设计.md) 的分工：11 回答「有哪些功能（F1~F8）」，
> 本文回答「这些功能长在**哪个界面**、怎么组织、什么状态该长什么样、怎么落地」。
> 与 [12 身份认证与权限落地](12-身份认证与权限落地设计.md) 的分工：12 定「信任链怎么修」，
> 本文只承接它的一条界面硬约束——**客户端不得再出现身份自选**。
>
> 本文的所有结论都基于对 `app/web/`（两个单文件 HTML）与 `app/routers/`（51 个接口）的逐行盘点，
> 每条缺口都标注了证据位置。**不含尚未存在的功能设想**，只把已有能力"长到界面上"。

---

## 0. 一句话问题定义

现在的界面是**能跑通的验证壳，不是产品**：两个 HTML 各自复制了一份 CSS、结果只有一种呈现、
交互反馈靠 `alert()`、F3/F4/F6/F7 的接口全部存在但**没有一个界面入口**。
更关键的是，产品最核心的差异化能力（F2 可信与口径透明）目前只是回答下面的一行小字，
而它是 11 §2 明确写下的「护城河」。

**本文的目标不是"把界面做漂亮"，而是把三条产品主张变成界面上可验证的东西**：

| 产品主张 | 界面上的可验证形态 | 当前状态 |
|---|---|---|
| 口径优先于智能（11 §0） | 口径**常驻可操作**，不是回答下面一行灰字 | ❌ 只是一行 `span` |
| 不可信必须显式标记（11 §0） | `source_stale` 整卡降级，不是一个小徽章 | ⚠️ 只有徽章 + 一行告警 |
| 拒绝也要完整（04 §1） | `denied` 有专属卡片、说清依据与下一步 | ❌ 与普通回答同一套渲染 |

## 1. 现状盘点（代码级事实）

### 1.1 已经做对、必须保护的界面决策

| 决策 | 证据 | 为什么必须保留 |
|---|---|---|
| 客户端与管理端**彻底分开**两个入口 | `app/main.py:4-7,75-86`（`/` 与 `/admin`） | 问数的人不管配置，管配置的人不在这里问数；混在一起必然导致权限模型崩溃 |
| 环境变量接管的配置项**只读**，并在界面上明确标注 | `app/web/admin.html:70-72`（`envLock/envTag/lockAttr`） | 生产密钥走 env，界面永远不可能覆盖它；这是"配置界面"该有的第一属性 |
| 数据源切换有"当前生效值"回显 + 只读声明 | `admin.html:148-180` | 换数据源是最高危操作，必须让人看见自己正连着哪套库 |
| 未配置模型时**走规则降级并显式告知**，而不是静默失败 | `admin.html:100-101`；`app/core/engine_bridge.py:45-52` | 区分「系统坏了」与「没装模型」，减少误报故障 |
| 驾驶舱**不做实时全量轮询** | `app/routers/reports.py:23-27` | 界面设计不能反过来要求后端拖垮源库 |

### 1.2 缺口清单（按"挡住产品化"的程度排序）

**U1 · 结果只有一种呈现，五态在界面上不存在** ⛔
- `index.html:105-151` 的 `render()` 只有一条路径：口径条 → 正文 → 表格 → 警告 → SQL → 反馈。
- 全仓搜 `need_clarify` 在 `app/web/` 下**只命中两处运营统计文案**（`index.html:214`、`admin.html:283`），
  也就是说：`need_clarify / denied / out_of_scope / meta / error / 空结果` 六种状态在界面上**都没有专属形态**。
- 后果：`denied` 与 `answered` 长得一样（都是"一段文字 + 没有表格"），用户无法判断自己是被拒绝了还是系统没数——
  这直接违反 11 §0 第 5 条「拒绝也要完整」。状态全集与逐态规范见 §3.3。

**U2 · 反问拿不到结构化选项，卡片式反问做不出来** ⛔（**契约缺口，必须先补**）
- 后端把歧义渲染成**纯文本**：`engine/pipeline.py:892-901` 的 `_render_clarify()` 输出
  `[规则ID] 问题 / 可选项：A / B / 默认按「X」计算`。
- 而 11 §F1.3 要求「以**卡片**反问，不是纯文本追问」。前端要靠正则去抠文本才能画卡片——不可接受。
- 好消息：这不是"缺数据"，是"缺暴露"。`amb` 里已经有 `id / ask / options / default`（`pipeline.py:894-899`），
  只需在 `engine_bridge.ask()` 的 payload 里多返回一个 `clarify` 数组。
- 链路已备好：`POST /api/ask/clarify` + `AskRequest.resolved:{规则ID:选择值}`（`app/routers/ask.py:62-67`、`app/models.py:15`）**全都已就绪，只差界面**。

**U3 · F3 分析能力全部没有界面**
- `compare / rank / trend / drill / attribution` 五个接口齐备（`app/routers/analysis.py:36-79`），
  `index.html` 里**一个调用都没有**（全仓 grep 无 `/api/analysis`）。
- 结果是"下钻/对比/趋势"这些 11 §F3 标注 MVP 的能力，用户只能靠换句话重问。

**U4 · 客户端保留了身份自选，直接踩 12 的 S1**
- `index.html:53-62` 有用户下拉框，且**第一项 `u001`（张院长）就是默认值**。
- 12 §2 第 4 条红线：「身份只能来自服务端授信」。界面不删掉它，红线无法成立。
- 替代方案已就绪：`GET /api/security/me`（`app/routers/security.py:16-18`）返回 `role / dept_scope / can_view_sql / can_export`，
  客户端应当**只读展示**"我是谁、我能看什么"。

**U5 · 客户端里有五个不可达的管理端分支（职责越界）**
- HTML 只声明了 2 个 tab：`我的驾驶舱 / 指标口径说明`（`index.html:77-80`）；
- 但 JS 里还有 `src / audit / ops / health / admin` 五个分支（`index.html:190-266`）。
- 这些是**审计、源域时效、平台状态、口径规则**——都属于后台。留在客户端里，
  一旦哪天有人加了按钮，就等于把审计与配置暴露给全体用户。

**U6 · F4/F5/F6/F7 的接口没有界面入口（后台功能缺口）**

| 已有接口 | 位置 | 界面 |
|---|---|---|
| `GET /api/security/audit/summary` | `security.py:32-47` | ❌ |
| `GET /api/security/roles` | `security.py:21-23` | ❌ |
| `GET /api/semantic/versions`、`GET /api/semantic/reconcile` | `semantic.py:65-89` | ❌（`reconcile` 后台 0 入口） |
| `GET /api/ops/backlog/export` | `ops.py:48-54` | ❌ |

| `GET/POST/DELETE /api/trust/pref`（偏好记忆 F2.2） | `trust.py:84-101` | ❌ |

| `GET /api/security/source/health`（只读守门体检） | `security.py:50-63` | ⚠️ 只在客户端死代码里 |

**U7 · 信任信息"有数据没渲染"**
- `caliber_bar` 每一项都有 `source` 字段（`app/core/caliber.py:54-56`，取值"提问"/"语义层"）——**界面丢掉了它**，
  而这正是"这个口径是语义层定的还是提问里带的"的追溯依据（`index.html:116` 只渲染 `key/value`）。
- `rollup: {applied, rolled}`（`app/routers/ask.py:44`）**未渲染**，上卷只靠一句塞进 `warnings` 的文字。
  11 §F2.7 要求"原细分完全不返回"，界面必须让用户看见"你问的层级被上卷了、上卷到哪"，否则会被理解成数据缺失。
- 四态里的 `restated` **没有任何产出路径**：`caliber.py:104-110` 定义了它，`_judge_maturity()` 从不返回它。
  界面按四态设计没问题，但必须标注"restated 待修正来源接入"，不能假装它已经能用。

**U8 · 交互与工程细节**
- 反馈/快照/复现/探测全部用 `alert()`（`index.html:157,162,166,280`）——阻塞式弹窗，无法携带跳转与详情。
- 两个 HTML **各复制了一份几乎相同的 CSS 令牌**（`index.html:7-46` 与 `admin.html:7-45`），
  已经出现分叉（客户端有 `.b-restated`，后台没有）。
- 没有任何图表：趋势与驾驶舱在界面上**只能用表格表达**（全仓无图表库）。

## 2. 界面分权：三个界面，不是两个

界面数量的第一性问题是**信任边界**，不是信息架构。

| 界面 | 使用者 | 承载 | 鉴权要求 | 会话 TTL |
|---|---|---|---|---|
| **问数客户端** `/` | 全院业务用户 | F1 对话、F2 可信透明、F3 分析、F4 看板与导出、**本人**历史与快照 | 普通登录态即可 | 8h + 空闲 30min |
| **语义层后台** `/admin` | 信息科 / 数据 PM | F5 资产、F6 授权、F7 运营、F8 平台 | 角色 ∈ {信息科} 且来源管理网段（12 §3.4） | 15min |
| **审计与授权台**（后台内的独立页，独立存储） | 审计员 / 安全 | 不可篡改审计链、授权变更留痕、导出追溯（12 §4.4/§6） | 独立角色，**与配置权分离** | 15min |

> 第三块**逻辑上必须独立**：12 §4.4 明确"授权变更 ≠ 数据访问，且同样不可篡改"。
> 界面上可以挂在后台里（少一个部署入口），但**导航、数据源、鉴权三者都要分开**。

## 3. 问数客户端：信息架构与组件规范

### 3.1 布局（三栏 + 常驻问句框）

```
┌──────────────────────────────────────────────────────────────────────────┐
│ 医院智能问数   我：医务处 李干事 · 医务处 · 可导出        [数据截至 10-16] │ ← 身份条（只读）
├────────────┬─────────────────────────────────────────┬───────────────────┤
│ 会话/历史  │  问句框（常驻顶部，支持 / 调指标）        │  口径抽屉（常驻）  │
│ · 今天     │ ┌─────────────────────────────────────┐ │ 时间范围 2026-09  │
│   出院人次 │ │ 上个月全院出院人次是多少    [提问]  │ │ 时间口径 出院日期 │
│ · 昨天     │ └─────────────────────────────────────┘ │ 科室归属 统计科室 │
│   耗占比   │  常见问法 chips（冷启动时展开）          │ 统计口径 按人次   │
│ · 更早     │ ─────────────────────────────────────── │ 指标版本 v1.3     │
│ · 我的快照 │  AnswerCard / ClarifyCard / DeniedCard   │ ── 可切换 ──      │
│            │  / OutOfScopeCard / NoDataCard / Error   │ □ 记住我的选择    │
│            │ ─────────────────────────────────────── │ ── 证据 ──        │
│            │  [下钻][对比][趋势][导出][反馈]           │ SQL / 快照 / 复现 │
└────────────┴─────────────────────────────────────────┴───────────────────┘
```

**三条布局决策的理由**：

1. **口径从"回答下面一行"提到常驻右栏**（F2.1→F2.2 的升级）。11 §2 把 F2 定为护城河，
   而护城河是**每次都要被看见**的东西；放在右栏才能做到"边看数边看口径"，并且切换口径后
   当前卡片原地刷新，而不是重问一遍。
2. **问句框常驻顶部而不是只有首屏**。多轮追问（F1.2「那心内科呢」）是最常用路径，
   输入框滚走会强迫用户回到顶部。
3. **左栏放"我的"历史与快照**。这一栏同时满足了 F2.5（可回溯）和 12 §6.3（快照限本人）。

### 3.3 状态映射表（**以代码为准**，修正 11 §3 的五态说法）

先说一个必须纠正的事实：11 §3 写的状态机是 `allow / need_clarify / denied / out_of_scope / no_data`，
而 `engine/pipeline.py` 实际只产出 **6 个 status**：

| 实现中的 status | 赋值点 | 对应 11 §3 的说法 |
|---|---|---|
| `answered` | `pipeline.py:849,860` | `allow`（名字不同，语义相同） |
| `meta` | `pipeline.py:928`（`meta_question` 意图） | **11 §3 漏了这一态**（"问口径"不查数，走这里） |
| `need_clarify` | `pipeline.py:808,829` | 一致 |
| `denied` | `pipeline.py:739,753,818` | 一致 |
| `out_of_scope` | `pipeline.py:808` | 一致 |
| `error` | `pipeline.py:783,793,798,839,855` | 一致 |
| ~~`no_data`~~ | **不存在** | 需界面判定，见下 |

> **`no_data` 在实现里不存在**：查询无结果时管线仍然回 `answered`，
> `_render_answer()` 只输出一句「共 0 行」（`pipeline.py:942-949`），`rows` 为空数组。
> 因此界面必须自行判定 `status === "answered" && rows.length === 0` → 空结果卡；
> 并且要区分**「无数据行」与「有一行但 cnt=0」**（后者是明确的 0，不能显示成"无数据"）。
> 这条判定是契约，不能靠前端各页各写一遍。

> **`meta` 态的补充说明**：模型（或 `app/core/rule_llm.py` 的降级 NLU）判断「问口径」时走这一态。
> 降级 NLU 原先没有这一分支，导致**没装模型的演示环境里 meta 卡永远出不来**（问"平均住院日是怎么定义的"
> 会落成"查询结果为空"），本次一并补上（`rule_llm.py` 的 `meta_question` 识别）。

界面呈现（每种状态一张专属卡片，**一眼可区分**）：

| status | 卡片 | 必须出现的元素 | 禁止 |
|---|---|---|---|
| `answered` | 结果卡 | 大号数字 → 口径条 → 成熟度 → 数据截止 → 图/表 → 追问建议 → 反馈 | 禁止在 `maturity != settled` 时不给提示 |
| `meta` | 口径说明卡 | 定义 / 公式 / 本院口径备注（`pipeline.py:918-929` 已渲染的字段）+ 指标版本 | 禁止出现导出与 SQL 入口（不查数，没有可导出的行） |
| `need_clarify` | 反问卡 | 一问一卡；选项为**可点按钮**；显示默认值；显示"为什么问"（规则 ID）；提供"按默认出数" | 禁止把选项做成纯文字；禁止回退到输入框重问 |
| `denied` | 拒绝卡 | 子类（越权 / 患者级 / 无范围）+ 结论 + 依据 + **下一步**（审批路径 / 联系信息科）+ "已留痕" | 禁止降级为反问（04 §1 红线）；禁止只说"暂不支持" |
| `out_of_scope` | 边界卡 | 缺什么（未注册指标名）+ "已进回流队列"（`backlogged` 已返回）+ 替代问法 | 禁止给出估算值 |
| 空结果（`answered`+空 rows） | 空结果卡 | 区分"确无数据"与"样本过小已抑制"；给出放宽建议 | 禁止把"无数据"显示成 0，也禁止显示成"共 0 行" |
| `error` | 故障卡 | 明确是**系统故障**（模型未配置 / 源库不可达 / 口径不合法），与"没权限""没数据"分开 | 禁止与空结果共用文案 |

**反问卡的具体形态**（U2 修完后即可实现）：

```
┌───────────────────────────────────────────────┐
│ 需要先确认一个口径，避免给您错误的数字          │
│                                               │
│ 时间口径按哪个算？            [规则 AMB-TIME]  │
│ ( ) 出院日期  ( ) 结算日期  (•) 入院日期       │
│ 若不指定，默认按「出院日期」计算                │
│                                               │
│ [按所选口径重算]   [按默认值直接出数]           │
└───────────────────────────────────────────────┘
       ↓ POST /api/ask/clarify {resolved:{"AMB-TIME":"出院日期"}}
```

### 3.4 关键交互规范

| 场景 | 规范 | 依据 |
|---|---|---|
| 切换口径 | **不覆盖**原答案：生成新卡片并标注"按新口径重算"，旧卡片保留 | F2.5 快照不可变 |
| 反问卡提交 | 「按所选口径重算」= `POST /api/ask/clarify` + `resolved`，口径由语义层的 `apply` 段写回 DSL（v0.14 起，不再往问句里拼口径词）；「按默认口径出数」= 提交 `resolved = {规则: default}`，管线视为"无需改动"。做不到的选项不提交就给数：卡片上已标注 `（暂不能自动应用）`，真选了会得到一份说明而不是一个换了口径的数字 | §3.3、docs/03 §6.1 |
| `source_stale` | 整卡降饱和 + 顶部横幅 + 数字前加"⚠" | 11 §5.2「不允许用户拿它当现状」 |
| 小样本上卷 | 显示"已从 X 上卷到 Y（原细分不返回）" | F2.7 |
| 追问/下钻 | 以卡片上按钮发起，自动携带上文（指标 + 时间 + 口径），**不要求用户重述** | F1.2 |
| 每次回答 | 页脚固定一行：快照号 · 数据截至 · 结果指纹 · 耗时 | F2.1/F2.5 |
| 加载态 | 骨架屏 + 阶段提示（召回/生成/校验/执行），因为一次问数可能 3s+ | 11 §6 首屏 ≤3s |

### 3.5 F3 分析交互（P4 已落地）

四个分析动作直接长在结果卡上：**下钻 / 排名 / 趋势 / 对比**（归因不在 MVP，见 §7 C10）。

| 动作 | 界面参数 | 请求 | 继承什么 |
|---|---|---|---|
| 下钻 | 维度（服务端给可用清单） | `POST /api/analysis/drill {answer_id, dimension}` | **全继承**：取快照里的有效 DSL 再加一维 |
| 排名 | 维度 + 最高/最低 + TopN | `POST /api/analysis/rank {question, dsl}` | 继承口径，替换分组 + 排序 |
| 趋势 | 时间粒度（日/周/月/季/年） | `POST /api/analysis/trend {question, dsl}` | 继承口径与时间范围，只改粒度 |
| 对比 | 同比 / 环比 | `POST /api/analysis/compare {question, dsl}` | 继承口径与范围，加一个对比期 |

**三条硬规矩**：

1. **分析不改口径**：动作从**上一次的有效 DSL**（口径写回之后，见 §7 C9）派生，
   只改分组维度 / 粒度 / 排序。所以分析卡上的口径条与上一张卡一致 ——
   想换口径请回口径条，不要靠"换个说法再问一遍"。
2. **维度可用性由服务端判定**（`GET /api/semantic/dimensions`）：
   可用 = 语义层声明 ∧ 权限允许 ∧ **当前数据源确实物化了**。
   前两条是口径与授权问题，第三条是**实现**问题 —— 实测 ADS 宽表就没物化
   `campus / pay_type / discharge_type / doctor`，界面若照声明给按钮，用户点下去只会拿到
   一条 `no such column`。不可用的维度照样列出来，但标注原因（§7 C11）。
3. **图表零依赖**：趋势用自绘 inline SVG 折线，排名/下钻用 CSS 柱状条，
   不引任何需要公网 CDN 的图表库（内网硬约束，§6.1）。

**对比的诚实处理（新增）**：本院数据只有 2023 年，`yoy` 的对比期一行都没有。
这时卡片必须明说"对比期在本院数据里没有记录，不能据此算同比/环比"，而不是让用户
把当期读成"同比 -100%"。这条由 `engine/pipeline.py::post_check` 出（§7 C11 附）。

### 3.6 对话流：一轮 = 一个容器（v0.16 落地）

**布局**（§3.1 的三栏）：左栏 = 会话历史 + 我的快照；中栏 = 常驻问句框 + 对话流；
右栏 = 口径（含可切换项与偏好记忆）+ 证据与反馈。

| 规则 | 做法 | 为什么 |
|---|---|---|
| 一轮一个容器 | `#ans-<n>` 唯一 id；卡片、证据区（`ev-<answer_id>`）、动作区（`act-<answer_id>`）、SQL 面板（`sql-<answer_id>`）全部挂在**该轮**上 | 只写"最后一张卡"的实现在多轮下必然串号：第二轮的下钻会读到第一轮的 DSL |
| 不覆盖历史 | 新的口径 / 新的分析 = 新轮次；只有**反问卡**在原轮次内替换（它还没有任何数字） | F2.5 快照不可变；用户要能指着上一张卡说"这个数不对" |
| 追问带上文 | 客户端只传 `session_id`，**上文由服务端按会话取**（上一轮有效 DSL） | 前端不该、也无法自己拼口径；口径的唯一来源是语义层 |
| 回放 | `GET /api/chat/sessions/{id}` 返回每轮的渲染载荷（rows 截断 200 行并标注） | 历史轮回必须能重建整段对话，而不是只留一句问话 |
| 归属 | 会话与快照都**限本人**（信息科可查全部）；越权一律 404 | 12 §6.3：历史本身就是敏感数据（谁在什么时候问了什么） |
| 身份切换 | 清空对话流与会话 ID | 换身份还留着上一个身份的上下文 = 越权读取 |
| 空态 | 没有会话时展示引导卡片 + 示例问句（`/api/ask/examples`）；已有会话时给追问建议（`/api/chat/examples`） | F1.7；也让用户知道"接着能怎么问" |

**多轮能力的边界要说清楚**：现在的指代消解是「模型看着上文改」+「降级规则有限改写」，
**引擎不做字段级强制合并**（§7 C13）。所以口径条必须常驻可见 —— 用户自己是最后一道检查。

### 4.3 指标编辑器：表单字段 ↔ 存储字段一一对应

界面不允许出现"语义层里没有的字段"，逐字段对齐 `MetricIn`（`app/models.py:39-53`）：

| 表单 | 字段 | 校验/交互规范 |
|---|---|---|
| 指标编码 | `code` | 新增时可填；编辑时只读（改码 = 换指标） |
| 名称 | `name` | 必填 |
| 定义 | `definition` | 必填；这是给用户"问口径"看的原文（`meta_question` 走这里） |
| 公式 | `formula` | 只展示不解析；**禁止界面做公式推导**（`semantic.py:5-7` ADR-03） |
| 类型 | `type` | ratio / count …（下拉） |
| 域 | `domain` | 影响 `source_stale` 判定（`caliber.py:113-117`），必须选 |
| 别名 | `alias[]` | tag 输入；这是召回质量的实际来源，界面要给"检验一下"的入口 |
| 支持的时间口径 | `supported_date_basis[]` | 多选；**口径切换的可选项只来自这里**（11 §F2.2）。⚠️ 取值实际定义在 **measure** 上（`date_basis.supported`），metric 只写 `default_date_basis` —— 由 `registry.caliber_options()` 解析后同名字段返回，界面与后台都读这一处（v0.16 修：此前直接读 metric 字段，永远为空，界面上的"口径切换"因此没有可选项） |
| 支持的科室口径 | `supported_dept_basis[]` | 多选（同上，来自 `dept_basis.supported`） |
| 敏感级 | `sensitivity` | public / internal / restricted；**旁边必须写清三级的可见性后果**（03 §2.0），因为 12 §1.2 S9 的坑就出在这里 |
| 责任人 | `owner` | **必填**，后端 400 强校验（`semantic.py:47-49`）；界面不能"跳过" |
| 上线状态 | `status` | online / offline |
| 变更说明 | `change_note` | 空则保存时提示"建议填写"，因为它进版本记录 |

### 4.4 后台的三条通用交互规范

1. **保存即留痕**：任何写操作后自动刷新「版本号 + 变更人 + 变更说明」，并提供"查看本次 diff"。
2. **高危操作二次确认 + 影响面**：`物理映射`、`口径规则`、`数据源切换`、
   `指标下线`四类保存前弹影响面面板（"影响 N 个指标 / 建议跑一次口径对账 / 建议跑 Golden 集"）。
3. **待配置要说出来**：接口返回 `pending_config`（如 `reconcile`）时，界面显示
   "还缺什么、由谁提供"，而不是空白表格 —— 这与客户端"拒绝也要完整"是同一条产品原则。

| 规则 | 说明 |

## 6. 前端工程化决策

### 6.1 一条硬约束决定了选型

**院内网无公网**：不能引 CDN、不能用需要外网拉包的运行时、字体与图标必须本地化。
这条约束下"用哪个框架"的重要性远低于"构建产物如何离线部署"。

### 6.2 两个方案与判定条件

| | A · 零构建渐进式（推荐 MVP） | B · Vite + Vue3 + ECharts |
|---|---|---|
| 形态 | `shared/` + `client/` + `admin/`，原生 ES Module + Web Component，产物即源码 | 构建为静态资源，由 FastAPI 挂载 dist |
| 部署 | 改一行即刻生效，无需 node 工具链 | 需在院内网准备 node 构建环境或提交构建产物 |
| 适用 | **当前阶段**：页面 2 个、团队以数据/后端为主、要能现场改 | 页面 ≥10、有前端人力 ≥2、要做复杂交互（拖拽建模、血缘图） |
| 代价 | 复杂交互（血缘图）以后要重写 | 离线部署与版本管理成本，安全评审要审 node 依赖链（医院信息科会问） |

**推荐：MVP 走 A，但必须做三件事**（否则会退化成更大的两个 HTML）：
1. CSS 令牌与基础组件收敛到 `app/web/shared/`；
2. 每个卡片一个文件（`AnswerCard.js` / `ClarifyCard.js` / `DeniedCard.js` …），按 `status` 路由渲染；
3. 图表用 **inline SVG 自绘**迷你图（趋势/对比/排名三类足够），不引图表库。

**v0.16 的实况与取舍**：第 3 条已做到（自绘 SVG 折线 + CSS 柱状）；
第 1、2 条**本轮仍未拆** —— 原因是验收脚本 `scripts/check_ui_states.js` 靠"抽取客户端里**唯一一个** `<script>`
在 Node 里执行"来工作，拆文件必须同步改抽取逻辑（改成读 `client/*.js` 清单）。
在拆之前，保持单文件是**可回归**的；拆成多文件但丢掉自动化验收才是真的退步。

| C9 | ✅ **已落地（v0.14）**：`resolved` 只跳过反问、不作用于 DSL | 用户选的口径**没有写回 DSL**：`resolved` 曾只出现在 `detect_ambiguity()`（跳过已澄清规则），没有任何一处在 DSL 构造后做合并；`aliases_map` / `conditional_default` 在 `engine/` 与 `app/` 中**均无读取方**（grep 0 命中）。**修法**：在语义层 `ambiguity_rules.yaml` 为每条规则声明 `apply`（`field`+`values` / `set` / `alias_to_default` / `unresolvable_values`），管线新增步骤 **4.5 口径写回**（早于权限门禁，因为口径可能换指标），写回后再跑一次 `validate_dsl`，不兼容就整批回退；**未声明映射的选项一律拒绝出数并说明原因**，不许拿默认口径顶替。`aliases_map` / `conditional_default` 已删除（前者内容并入 `apply.values`，后者与 registry 的 `*.default` 重复） | 用户选「结算日期」而系统按默认口径出数：**界面若显示"已按所选口径重算"就是撒谎** |
| C12 | ✅ **已落地（v0.16）**：**没有"会话"这个概念**，于是 F1.2 的多轮追问无处落地 | 此前客户端是"一问一卡"，每次提问都是全新一轮：用户问完 2023 年出院人次再问「那心内科呢」，系统只能把他当陌生问题（`rule_llm` 直接 out_of_scope，模型也看不到任何上文），"继承上文口径"全靠用户重述。**修法**：① 新增会话/消息模型（`chat_session` / `chat_message`）与 `/api/chat`（含**软删**与**他人会话 404**）；② `AskPipeline.ask(context=…)` 把上一轮**实际执行的有效 DSL**（口径写回之后那份，不是模型原始输出）注入提示词，并记 `context_in` 到 trace 供审计排查 —— 契约是 `build_prompt` 的【对话上文】块，两边改动必须同步；③ 降级 NLU 侧实现**有限的**指代消解（换粒度/换范围/加对比/指定或排除科室），**取不到上文就明确 out_of_scope，绝不猜** | 上下文必须是"同一会话内"，跨会话/跨用户传递 = 越权读取 + 口径污染 |
| C14 | ✅ **已落地（v0.17）**：指标写入是**整条替换 + 默认值静默改写** | 两个连着的坑，都在"界面接入写接口"时才暴露：① `upsert_metric` 用 `metrics[i] = metric` **整条替换**，而接口字段集只来自 `MetricIn`（`measure` / `dimensions` / `default_date_basis` 都不在其中）→ 用户在界面上只改一个"名称"，就会把指标与度量的绑定、可用维度一起删掉，指标立刻变成查不出数的僵尸条目，版本记录只写"改名"；② `MetricIn` 给 `type/sensitivity/status` 设了"看起来合理"的默认值（`ratio` / `public` / `online`），于是任何只发 `{code,name,owner}` 的调用都会把 `restricted` 悄悄降成 `public`、把已下线指标重新上线。**修法**：写入改为**合并语义**（`None` = 未提供 = 保留原值，`[]`/`""` = 显式清空），默认值只在**新建**时由 `upsert_metric` 补，并返回 `changed[]` 供界面回显"变更了哪些字段" | 这类坑的共同代价是"错得无声"：用户以为只改了名字/责任人，实际改了敏感级 |
| C13 | ⏳ **待办（本轮只做了一半）**：多轮继承依赖模型，引擎不做强制合并 | 现在的多轮是「模型看着上文自己改」+「降级规则有限改写」，**引擎不做字段级 merge**。风险：模型可能只继承指标却换了时间范围（或反之），产生"半继承"——用户以为还在看 2023 年，实际拿到的是上月。**做法**：在管线里加一步 `inherit_dsl(prev, fresh, question)`，逐字段判定"本轮是否显式提到"（时间区间 / 粒度 / 科室过滤 / 口径参数），未提到则强制沿用，并在 trace 里逐项记录"继承 / 覆盖 / 新增"；再补一组 selftest（对照"显式改口径必须覆盖"与"未提到必须继承"） | 未做之前，界面上必须让口径条**始终可见**（本轮已做到：右栏常驻 + 每张卡口径条），用户能自己发现口径没跟着走 |

UI-2/UI-3 与 12 §7 的 A2/A7 联动：界面验收只验"呈现"，数据层正确性由 `engine/pipeline.py --selftest`（37 项）与

**已自动化**（不依赖浏览器，可在院内网 / CI 跑）：

```
uvicorn app.main:app --port 8020     # 另开一个窗口（demo 环境可用 ASK_DS=ads ASK_LLM_MOCK=1）
node scripts/check_ui_states.js      # 69 项：六态识别 + 口径写回（选了必须生效）+ 卡片该有/不该有什么
                                     #        + 对话流端到端（boot → 提问 → 追问不覆盖 → 口径抽屉 → 会话越权 404）

# 管理端验收（会写语义层，所以必须指向**副本**）
copy semantic-layer\metric_registry.yaml var\_admin_check_registry.yaml
$env:ASK_REGISTRY="var\_admin_check_registry.yaml"; uvicorn app.main:app --port 8032
node scripts/check_admin_states.js http://127.0.0.1:8032   # 24 项
```

`check_admin_states.js` 内置一道保险：读 `/api/admin/registry` 确认语义层路径里含 `_admin_check`，
否则**跳过全部写操作** —— 验收脚本不能有"改坏真实资产"的可能。它验的是三类事：
① 门禁与管理端身份（非信息科不渲染后台骨架）；② 指标编辑器的界面不变式（责任人必填、公式不解析、
敏感级写明后果、`measure` 只读、口径多选与提交选择器一致）；③ 写接口契约（**只改一个字段不许抹掉
其它字段、不提交的字段不许被默认值静默改写**）。

Node 端的 DOM 桩已升级到能跑 `boot()` / 提问 / DOM 分支（`insertAdjacentHTML` / `children` / `window`），
并把客户端的相对 `fetch` 补上 base —— 于是「第 2 轮追加而不是覆盖第 1 轮」这类**只有真实 DOM 才暴露**的
问题也进了回归。仍然不验样式与布局（那需要浏览器）。

做法是把 `app/web/index.html` 里的客户端脚本抽出来在 Node 里跑，喂**真实接口返回的 payload**，
断言产出的 HTML：例如"反问卡里必须出现 radio 且不得出现任何数字"、"非授权角色不得出现 SQL 入口"、
"空结果卡必须与数字 0 区分"。这不是浏览器测试的替代品（不验样式与布局），但能把
「六种状态各渲染成一张不同的卡」这件事变成可回归的断言。
