# 04 · 问数引擎设计

> 定位：L5 是**可替换的耗材层**。换模型不应影响指标口径，这条边界必须守住。

## 1. 整体 Pipeline

```
              用户输入「上个月心内科平均住院日同比怎么样？」
                              │
              ┌───────────────▼────────────────┐
              │ 0. 患者级门禁（合规一票否决）    │  ← 命中即 denied，不进 LLM
              └───────────────┬────────────────┘
                              ▼
              ┌──────────────────────────────┐
              │ 1. 指标/维度召回（混合检索）    │
              │    向量 + BM25 + 别名精确匹配   │
              └───────────────┬──────────────┘
                              ▼
              ┌──────────────────────────────┐
              │ 2. 受限生成 → 输出查询 DSL      │
              │    （不是 SQL！）含回炉 ≤2 次   │
              └───────────────┬──────────────┘
                              ▼
              ┌──────────────────────────────┐
              │    3. DSL 校验（schema + 口径）    │
              └───────────────┬──────────────┘
                              ▼
              ┌──────────────────────────────┐
              │ 4. 意图分流：meta/超范围/查数   │  ← 前两者不反问、不出数
              └───────────────┬──────────────┘
                              ▼
              ┌──────────────────────────────┐
              │ 4.5 口径写回（resolved → DSL） │  ← ★ 必须早于权限：口径可能换指标
              └───────────────┬──────────────┘
                              ▼
              ┌──────────────────────────────┐
              │ 5. 权限门禁（行级 + 维度级）    │  ← ★ 必须早于反问
              └───────────────┬──────────────┘
                              ▼
              ┌──────────────────────────────┐
              │ 6. 歧义检测 → 反问澄清         │  ← 只在「有权 + 要查数」时
              └───────────────┬──────────────┘
                              ▼
              ┌──────────────────────────────┐
              │ 7. 语义层 → SQL → 执行         │
              └───────────────┬──────────────┘
                              ▼
              ┌──────────────────────────────┐
              │ 8. 结果校验（空/量级/小样本）   │
              └───────────────┬──────────────┘
                              ▼
              ┌──────────────────────────────┐
              │ 9. 可视化选择 + 自然语言解读    │
              └───────────────┬──────────────┘
                              ▼
                  输出：图/表 + 口径说明 + SQL 可展开
                        + 数据来源 + 数据成熟度 + 反馈按钮
```

> ★ **顺序不是实现细节，是安全边界**（v1.1 由自测反推修正）：
> - 反问若早于权限门禁，越权请求会先被反问掉 —— 既漏放（status 变成 need_clarify），
>   又泄露「这份数据存在」。实测 G0003/G0008 两条越权用例就是这样漏掉的。
> - 患者级门禁必须最前：意图分类可能把「患者名单」判成 `out_of_scope`，
>   但合规上必须记为 **denied 并留痕**，不能只回一句「暂不支持」。
> 参考实现：`engine/pipeline.py :: AskPipeline.ask`。

## 2. 模块一：意图分类

| 意图 | 说明 | 后续链路 |
|---|---|---|
| `query_metric` | 查指标 | 主链路 |
| `query_detail` | 查明细（受控） | 需二次审批 |
| `compare` | 对比（科室间、时间间） | 多序列查询 |
| `rank` | 排名 Top N | 排序查询 |
| `attribution` | 归因（"为什么涨了"） | P3，维度拆解 |
| `trend` | 趋势 | 时间序列 |
| `forecast` | 预测 | P3 |
| `meta_question` | 问口径（"药占比怎么算的"） | 直接返回指标定义 |
| `chitchat` | 闲聊 | 礼貌引导 |
| `out_of_scope` | 越权/超范围 | 明确拒绝 |

**实现建议**：意图分类用**规则 + 小模型**（如 Qwen2.5-7B 微调或 few-shot），不要用大模型全量过一遍——省 token、降延迟、易纠偏。规则层优先拦截 `out_of_scope`（如"把张三的病历给我"）。

## 3. 模块二：反问澄清

### 3.1 触发条件（v1.1：**全部满足**才反问）

> ⚠️ 本节在 v1.1 做过方向性修正。原写法是「任一命中即反问」，
> 实测在 30 条 Golden 集上反问率接近 50%，产品不可用（G0004「各科室排名前10」
> 这种表达明确的问句也被反问）。**反问是稀缺资源，只能花在真正会改变数字的地方。**

触发必须同时满足 N1~N5：

| | 条件 | 说明 |
|---|---|---|
| **N1** | 命中 `triggers`（或 `trigger_on: dept_mentioned`） | 科室归属歧义按「问题中是否点名具体科室」判定，而不是裸词「科室」 |
| **N2** | 问题中**没有** `explicit_markers` | 用户已自带消歧信息（如「住院收入」「31天非计划」） |
| **N3** | 该口径的 `supported` 长度 ≥ `supported_min` | 指标只有一个可选口径时，问了也没有第二个答案 |
| **N4** | 上下文中无已澄清/已记忆的口径 | `resolved` + 用户偏好（AMB-004 `remember_user_choice`） |
| **N5** | DSL 侧未消歧（`dsl_check`） | 如 `compare` 已指定 yoy/mom，就不再问「同比还是环比」 |

三条**硬否决**（优先级高于 N1~N5）：

| | 规则 | 理由 |
|---|---|---|
| **R1** | `meta_question` / `out_of_scope` 不反问 | 用户只是问「药占比怎么算的」，反问口径属于答非所问 |
| **R2** | 权限判定拒绝时不反问 | 先拒绝；反问会泄露「这份数据存在」 |
| **R3** | `ask_mode: echo_only` 的规则只回显、不反问 | 本院已有统一默认、差异在口径卡片明示并可一键切换 |

补充触发（与词表并列）：

2. 指标召回 top1 置信度 < 0.75
3. 召回 top1 与 top2 分数差 < 0.08（难以区分）
4. 时间范围缺失或模糊（"最近"）→ **缺失时直接拒绝出数，禁止用默认时间**
5. 用户历史中该问题曾被打回

> ★ **禁止默认时间范围**：`dsl_from_dict` 会把缺失的 `time` 兜底成 `last_month`，
> 若不拦住，模型「忘了给时间」也能出数，用户拿到的是一个**口径不明的数字**
> —— 这是最难被发现的一类静默错误。

### 3.2 反问的原则

- **一次最多问 2 个问题**，多了用户会烦。
- **给默认值 + 选项**：「按【出院日期】统计可以吗？（也可选入院日期）」—— 允许一键确认。
- **记住用户偏好**：用户选过"科室口径=开单科室"后，后续默认沿用，并在界面显示可切换。
- **不要反问已知信息**：用户是心内科主任，"我的科室" 不需要反问。

### 3.3 反问提示词片段

```
你是医院数据分析助手。用户问题存在以下歧义：{ambiguity_list}
请生成一句简短（≤40字）、专业的中文反问，给出推荐默认值和 2-3 个选项。
语气礼貌，不要罗列技术术语。不要解释公式。

用户问题：{question}
默认推荐：{default_choice}

输出 JSON：{"ask": "...", "options": ["...", "..."], "default": "..."}
```

---

### 3.4 口径写回：用户选了口径，就必须真的生效（v1.2 新增）

反问只是把口径问清楚。**问清楚之后没改到 DSL 上，就等于没问** ——
这是 v1.1 的一个真实事故（docs/13 §7 C9）：`resolved` 被用来跳过反问，
却没有任何一处把选项写回 DSL，于是用户选「结算日期」、系统按默认口径出数，
界面还显示"已按所选口径重算"。

| 环节 | 规则 |
|---|---|
| 映射来源 | **语义层** `ambiguity_rules.yaml` 的 `apply` 段（`field`+`values` / `set` / `alias_to_default` / `unresolvable_values`）。代码只认识 DSL 路径（`APPLY_PATHS`），不认识任何业务口径 |
| 生效时机 | 步骤 4.5，**早于权限门禁**：口径可能换掉指标（`AMB-001` 换 op_visit_cnt），权限必须按最终指标判定 |
| 二次校验 | 写回后再跑一次 `validate_dsl`；若与当前指标不兼容（如给门诊指标选了「出院日期」）→ **整批回退**，要求用户重新确认，不许"应用失败还照出数" |
| 做不到的选项 | 拒绝出数：`status=need_clarify` + 说明原因 + 可改选项，**不许拿默认口径顶替**（宁可说不会，不可编造 —— docs/11 §1） |
| 等同默认 | 选项等于该规则 `default`，或被声明在 `apply.alias_to_default`（院方认可的同义说法，如「住院期间死亡」= 院内死亡）→ 视为无需改动 |
| 前端配合 | 反问项带 `options_detail`，逐项标注 `appliable` 与原因，避免用户选一个注定得不到答案的选项 |

**回归保障**（`python engine/pipeline.py --selftest`）：
写回生效（AMB-011/012/013/004）、未声明映射必须拒绝、等同默认正常出数、
映射与指标不兼容必须回退、以及**映射表静态自检**
（路径合法 / 取值在枚举内 / 指标已注册 / 每个选项都被显式分类）。

## 4. 模块三：指标/维度召回

### 4.1 三级检索策略

| 级别 | 方法 | 作用 | 权重 |
|---|---|---|---|
| L1 **别名精确匹配** | 指标 `alias` 字典树/AC 自动机 | 命中即高置信，直接锁定 | 直接采纳 |
| L2 **BM25 关键词** | 对 `name + alias + business_definition` 建索引 | 处理字面相似 | 0.4 |
| L3 **向量语义召回** | 对 `definition + notes` 做 embedding | 处理口语化表达（"住院待多久"→平均住院日） | 0.6 |

融合：`score = 0.4 * bm25_norm + 0.6 * cos_sim`，取 top-5 连同定义一起喂给 LLM 做最终选择。

### 4.2 示例库（Few-shot）召回

维护 `question → DSL` 示例对（Golden 集的孪生资产），取语义最相似的 3~5 条作为 few-shot 示例。**这是提升准确率性价比最高的手段**，比调提示词有效。

```yaml
examples:
  - q: 上个月各科室出院人次排名
    dsl: {metrics: [ip_discharge_cnt], dimensions: [dept], time: {granularity: month, range: {type: last_month}}, options: {order_by: {metric: ip_discharge_cnt, dir: desc}}}
  - q: 心内科平均住院日同比
    dsl: {metrics: [ip_los_avg], filters: [{field: dept, op: '=', value: 心内科}], time: {granularity: month, range: {type: last_month}, compare: {type: yoy}}}
```

### 4.3 冷启动建议

先人工写 **80~120 条**高频问答对（来自真实月报/会议纪要/领导常问问题），覆盖 30 个核心指标。这比任何算法优化都值钱。

## 5. 模块四：受限生成（核心）

### 5.1 为什么不生成 SQL

| 生成 SQL | 生成 DSL |
|---|---|
| 搜索空间无限，错误率高 | 搜索空间受限于已注册指标 |
| 口径可能算错 | 口径由语义层保证 |
| 无法注入权限（要解析 SQL） | 天然可在语义层注入 RLS |
| 换数据库要改 | 换数据库只改语义层 |
| SQL 注入风险 | 结构化输出，无注入 |

### 5.2 生成提示词模板（骨架）

```
# 角色
你是某三甲医院的数据查询助手。你的唯一任务：把用户的中文问题，
转换为符合给定 Schema 的查询 DSL（JSON）。禁止输出 SQL，禁止输出解释。

# 硬性约束
1. 只能使用【可用指标】列表中出现的 metric_code，不得编造。
2. 只能使用【可用维度】列表中出现的 dimension code。
3. 若用户需要的指标不在列表中 → 输出 {"intent":"unsupported_metric","suggest":"..."}
4. 不要计算任何医疗公式，复合指标（如平均住院日）直接使用其 metric_code。
5. 时间必须明确；"最近/近期" 默认映射为最近 6 个月。
6. 若存在歧义且无法从上下文推断 → 输出 {"intent":"need_clarify","ask":"..."}
7. 输出 confidence（0-1）。低于 0.7 必须走 need_clarify。

# 当前上下文
今天：{today}
用户角色：{role}｜可访问院区：{campuses}｜可访问科室：{depts}｜默认科室口径：{dept_basis}

# 可用指标（top5 召回）
{metrics_with_definition}

# 可用维度
{dimensions}

# 参考示例
{few_shot_examples}

# DSL Schema
{dsl_json_schema}

# 用户问题
{question}

# 输出
仅输出 JSON，无 markdown 代码块标记。
```

### 5.3 输出校验（生成后必做）

```python
def validate_dsl(dsl, registry, user_ctx) -> tuple[bool, str]:
    # 1. schema 校验（Pydantic）
    # 2. metric_code 存在性校验
    # 3. dimension 是否被该 metric 支持
    # 4. date_basis / dept_basis 是否在 supported 列表内（★ 防止 LLM 编造口径）
    # 5. 权限校验：科室/院区是否在用户可见范围
    # 6. 时间范围合理性（不能查未来、跨度不超过 5 年）
    # 7. 患者级指标是否触发审批
    return ok, err_msg
```

失败 → 携带 `err_msg` 回炉重生成（最多 2 次）→ 仍失败 → 转模板化路线 C → 再失败 → 转人工。

## 6. 模块五：执行与自我修正

| 错误类型 | 处理 |
|---|---|
| SQL 语法错误 | 携错误信息回炉重生成（≤2 次） |
| 查询超时 | 自动降级到预聚合 ADS 表 / 缩小时间范围 |
| 返回空结果 | **不要直接说"没有数据"**，先自查：时间口径是否错、科室名是否匹配、过滤条件是否过严；仍空则提示可能的口径问题 |
| 返回量级异常 | 与历史同口径对比，偏离 > 3σ → 加"数据异常"角标 + 提示联系数据管理员 |
| 权限拒绝 | 明确告知"您无权查看该科室数据"，并给出申请入口 |

**红线**：**绝不允许为了"有答案"而放宽口径或猜测数值。**

## 7. 模块六：结果校验规则

| 检查 | 规则 | 动作 |
|---|---|---|
| 空值 | 结果集为 0 行 | 提示 + 口径自查建议 |
| 分母为 0 | ratio 指标分母 = 0 | 返回"—"而非报错 |
| 量级漂移 | 同比/环比偏离 > 200% | 数据异常角标 |
| 数据成熟度 | 含 `provisional` 数据 | 灰色 + "未结算"角标 |
| 四舍五入 | 比率类保留 2~4 位 | 前端统一格式化 |
| 单位一致性 | 元 / 万元自动切换（> 1亿自动转万元/亿元） | 前端处理 |

## 8. 模块七：可视化选择与解读

### 8.1 图表自动选择规则

| 数据形态 | 图表 |
|---|---|
| 单值 + 同比 | 指标卡（大字 + 涨跌箭头） |
| 时间序列 | 折线图 |
| 单维度分类对比 | 横向柱状图（科室名长，横向更友好） |
| 排名 Top N | 条形图 |
| 时间 × 维度 | 堆叠柱/热力图 |
| 占比构成 | 饼图/环图（分类 ≤ 6） |
| 两个指标关系 | 散点图 |

### 8.2 自然语言解读（模板 + LLM 混合）

**关键**：解读的**数字必须由系统填充**，LLM 只负责组织语言，防止数字幻觉。

```
【模板】
{metric_name}在{period}为{value}{unit}，{direction_word}{delta}{unit}（{delta_rate}%），
{dimension_summary}。

【LLM 补充】
基于以上事实，用一句话说明业务含义（≤50字），不引入新数字，不做归因推断除非数据支持。
```

示例输出：

> 平均住院日在 2026年9月 为 **8.42 天**，同比下降 0.31 天（-3.55%）。
> 全院 32 个临床科室中，心内科（11.2 天）、神经外科（10.8 天）高于全院均值。
>
> 📌 口径：按【出院日期】统计 · 科室归属【出院科室】 · 数据已结算
> 🔍 查看 SQL | 指标定义 | 👍 👎

## 9. 缓存与成本优化

| 层级 | 策略 | 命中率预期 |
|---|---|---|
| L1 结果缓存 | `hash(dsl + 数据版本)` → Redis，TTL 到下次跑批 | 30~40%（重复提问多） |
| L2 语义缓存 | `embedding(question)` 相似度 > 0.95 → 复用结果 | 10~15% |
| L3 预聚合 | 热门指标组合预计算入 ADS | 50%+ 查询直接走 ADS |
| L4 模型路由 | 意图分类/反问用 7B；DSL 生成用 14B~32B；复杂归因才上大模型 | 成本降 60%+ |

**典型成本估算**（单院，日均 500 次问数）：
- 7B×4 次调用 + 32B×1.5 次调用 ≈ 每天 8k~15k tokens/次 × 500 ≈ 5M tokens/天
- 私有化 GPU（L20/A10）可完全承载，无边际 API 成本

## 10. 评估体系（最重要的一节）

### 10.1 Golden 集构建

| 项 | 要求 |
|---|---|
| 规模 | MVP ≥ 300 条；成熟期 ≥ 1500 条 |
| 来源 | 真实会议纪要、月报问题、科室主任访谈、历史工单 |
| 结构 | `{question, expected_dsl, expected_sql, expected_result_hash, ambiguity_flag, role, dept_scope}` |
| 标注 | 由业务 + 数据团队双人交叉标注，分歧由指标责任人裁决 |
| 覆盖 | 30 个核心指标 × 维度组合 × 时间表达（"上个月"/"上季度"/"今年 3 月"）× 歧义/非歧义 |
| 维护 | 每次线上打回的案例，48h 内补入 |

### 10.2 评估指标

| 指标 | 定义 | MVP 目标 |
|---|---|---|
| 意图准确率 | 意图分类正确 / 总数 | ≥ 90% |
| 指标召回率@5 | 正确指标在 top5 内 | ≥ 95% |
| 指标选择准确率 | top1 命中 | ≥ 92% |
| DSL 可执行率 | 生成的 DSL 能通过校验并执行 | ≥ 92% |
| **结果正确率** | 结果与 Golden SQL 结果一致（容差 0.01） | **≥ 90%** |
| 反问得当率 | 该反问时反问了 / 应反问总数 | ≥ 80% |
| 误反问率 | 不该反问却反问 / 总数 | ≤ 10% |
| 拒绝正确率 | 越权/超范围被正确拒绝 | = 100% |
| P95 延迟 | 端到端 | ≤ 8s |
| 用户采纳率 | 未重问且未打回 | ≥ 60% |

### 10.3 回归流程（CI 化）

```
每次改动（模型 / 提示词 / 语义层 / 召回策略）
        │
        ▼
自动跑 Golden 集（约 10~20 分钟）
        │
        ▼
生成对比报告：各项指标 vs 上一版本
        │
        ▼
「结果正确率」不得下降；任一指标下降 > 2pt → 阻断发布
        │
        ▼
人工抽检 30 条 diff 案例
        │
        ▼
通过 → 灰度 10% 用户 → 全量
```

**这一条必须做 CI**。没有回归集的问数产品等于蒙眼开车。

### 10.4 准确率提升路线（经验优先级）

| 优先级 | 手段 | 预期提升 |
|---|---|---|
| 1 | 扩充 Few-shot 示例库（80 → 300 条） | +8~15 pt |
| 2 | 优化指标 `alias` 与 `business_definition` 的文案 | +5~10 pt |
| 3 | 歧义词表反问机制 | +5~8 pt（并大幅降低"错得很自信"） |
| 4 | 混合检索（BM25 + 向量）调优 | +3~5 pt |
| 5 | 输出校验 + 回炉修正 | +3~5 pt |
| 6 | 领域微调（Qwen2.5-14B 上 LoRA 微调 NL→DSL） | +5~10 pt |
| 7 | 换更大模型 | 边际递减，成本高 |

> **优先做 1、2、3**。微调与换大模型的性价比远低于把指标定义和示例库写好。

                  ┌────────────────────┐
                  │  模型服务不可用     │

## 12. 工程 checklist

- [ ] LLM 只输出 DSL，不输出 SQL（可用 JSON Schema / function calling 强制）
- [ ] 所有数字由系统填充，LLM 不生成数字
- [ ] 低置信度强制反问，禁止猜测
- [ ] Golden 集 + CI 回归在 MVP 阶段就建立
- [ ] 每次响应都回显：口径 + 数据来源 + 数据成熟度 + SQL 可展开
- [ ] 打回按钮 → 自动沉淀到错误案例库
- [ ] 模型可插拔（配置化，一次改动切换 Qwen/DeepSeek/GLM）
- [ ] 模型服务不可用时可降级到手动指标选择器
