# 01 · 架构总体方案

## 1. 产品定位与目标

### 1.1 定义

**医院智能问数**：让医院管理者、临床科室主任、运营/质控/医保专员，用自然语言（中文口语）提出数据问题，系统在秒级返回**口径正确、可追溯、可解释**的聚合结果与解读，并支持下钻、对比、归因与导出。

### 1.2 与非"问数"产品的边界

| 能力 | 是否属于本产品 | 说明 |
|---|---|---|
| 自然语言查指标 | ✅ 核心 | 主场景 |
| 自动生成周报/月报 | ✅ 核心 | 模板化 + 解读 |
| 异常自动发现与预警 | ✅ P3 | 从"人问"到"机器主动说" |
| 归因分析（为什么涨/跌） | ✅ P3 | 维度拆解 + 贡献度 |
| 患者级明细检索 | ⚠️ 受控 | 需审批 + 审计，默认不开 |
| 科研队列构建 | ➖ 独立产品 | 建议走 OHDSI ATLAS |
| 临床决策支持（CDSS） | ❌ 不属于 | 属诊疗域，合规要求不同 |

### 1.3 成功标准（建议立项时写死）

| 指标 | MVP 目标 | 成熟期目标 |
|---|---|---|
| 意图识别准确率 | ≥ 90% | ≥ 96% |
| 查询可执行率 | ≥ 92% | ≥ 98% |
| **结果正确率**（vs 人工核验） | **≥ 90%** | **≥ 95%** |
| 反问得当率 | ≥ 80% | ≥ 90% |
| 首字/首屏响应 | ≤ 3s | ≤ 1.5s |
| 完整查询 P95 | ≤ 8s | ≤ 5s |
| 用户采纳率（不重问） | ≥ 60% | ≥ 80% |
| 覆盖核心指标数 | 30~50 | 300+ |

> ⚠️ 正确率是本产品的**生死线**。医院用户一旦发现一个错数字，信任归零且极难挽回。宁可反问、宁可说"我不会"，不可编造。

## 2. 用户角色与核心场景

| 角色 | 典型问题 | 特征 |
|---|---|---|
| 院长 / 副院长 | "上个月全院门诊量同比多少？""DRG 盈亏情况？" | 宏观、要趋势、要有解读 |
| 医务处 | "各科室平均住院日排名""非计划重返率" | 质控口径、要排名 |
| 运营管理部 | "某科室次均费用为什么涨了？" | 要归因、要下钻 |
| 医保办 | "DIP 分组盈亏、高低倍率病例占比" | 医保口径、政策敏感 |
| 财务处 | "医疗收入结构、药占比、耗占比" | 财务口径、要精确 |
| 临床科室主任 | "我科本月出院人次、CMI、四级手术占比" | 单科室、横向对比 |
| 药学部 | "抗菌药物使用强度、基药占比" | 专项指标 |

**MVP 建议只选 1~2 个角色的 30 个指标切入**（推荐：院长运营驾驶舱 或 医务质控月报）。

## 3. 总体架构（六层）

```
┌──────────────────────────────────────────────────────────────┐
│  L6 应用层                                                     │
│  对话问数 │ 院长驾驶舱 │ 自动月报 │ 异常预警 │ 行动工单/闭环   │
├──────────────────────────────────────────────────────────────┤
│  L5 智能层（问数引擎）——「耗材层，可换模型」                    │
│  意图路由 │ 反问澄清 │ 指标召回 │ 受限生成 │ 自我修正 │ 解读   │
├──────────────────────────────────────────────────────────────┤
│  L4 安全合规层                                                 │
│  SSO/RBAC │ 行级列级权限 │ 脱敏 │ 患者级围栏 │ 全量审计       │
├──────────────────────────────────────────────────────────────┤
│  L3 语义层 ★核心资产                                           │
│  指标定义 │ 维度 │ 时间口径 │ 血缘 │ 版本管理 │ 审批流程       │
├──────────────────────────────────────────────────────────────┤
│  L2 数据治理层                                                 │
│  ODS→DWD→DWS→ADS │ 主数据/字典映射 │ 数据质量 │ 调度          │
├──────────────────────────────────────────────────────────────┤
│  L1 数据源                                                     │
│  HIS EMR LIS PACS HRP 医保 DRG/DIP 物资 财务 体检 随访 专病库  │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 各层职责边界（避免越界的关键约定）

| 层 | 负责 | **不负责** |
|---|---|---|
| L1 | 提供原始数据 | 任何业务口径 |
| L2 | 清洗、标准化、建模、质量 | 定义"指标叫什么" |
| L3 | **定义指标唯一口径、维度、时间基准** | 存数据、算数据 |
| L4 | 谁能看什么、脱敏、留痕 | 判断语义 |
| L5 | 理解人话 → 选出正确的指标+维度+时间 | **推导业务公式** |
| L6 | 呈现、交互、闭环 | 口径正确性 |

> **铁律**：L5 绝不自己推导医疗公式（如平均住院日）。所有计算必须由 L3 定义的指标/度量完成，L5 只做"选择"和"组合"。

## 4. 数据流向

```
[业务库 CDC/定时抽取]                [文件/接口]
        │                                 │
        └──────────► ODS（原始镜像，只读，保留历史）─────────┘
                         │
                    [清洗 / 标准化 / 主数据映射]
                         ▼
                    DWD（明细事实 + 一致性维度）
                         │
              ┌──────────┴──────────┐
              ▼                     ▼
          DWS（主题宽表）       OMOP CDM（临床/科研）
              │
        [指标计算 · 预聚合]
              ▼
          ADS（指标结果表 / 应用层宽表）
              │
     ┌────────┴────────┐
     ▼                 ▼
 L3 语义层          Superset / 驾驶舱
（口径定义 + 查询生成）
     │
     ▼
 L5 问数引擎 → L6 前端
```

### 4.1 时效性策略

| 数据域 | 刷新频率 | 说明 |
|---|---|---|
| 门诊/住院运营日报 | T+1（凌晨 2:00 跑批） | 主流 |
| 财务收入 | T+1 或月结后重算 | 结算日期晚于出院日期，需回刷 |
| DRG/DIP 分组结果 | 月度（分组器跑批后） | 分组器版本要记录 |
| 床位/在院实时监控 | 分钟级（只读专用视图） | 严禁写生产库 |
| 检验检查 | T+1 | |

> 财务类指标必须支持**回刷**：上月数据在本月 5 日后可能因补结算而变化。语义层需标记 `data_maturity: settled | provisional`。

## 5. 三条技术路线决策（关键）

| 路线 | 做法 | 准确率 | 覆盖度 | 风险 | 结论 |
|---|---|---|---|---|---|
| **A. Text-to-SQL 直连** | 表结构喂给 LLM 生成 SQL | 60~80% | 高 | 口径错误、SQL 注入风险、性能不可控 | ❌ 不裸用于生产 |
| **B. Text-to-Metric**（语义层驱动） | LLM 只输出「指标 + 维度 + 时间 + 过滤」，由指标引擎生成 SQL | 90~98% | 中（受指标数量约束） | 指标覆盖不足 | ✅ **主路线** |
| **C. 模板化问数（NL2DSL）** | 预置分析场景，槽位填充 | ≥99% | 低 | 场景有限 | ✅ **兜底 + 冷启动** |

### 5.1 推荐策略：B 主 + C 兜底 + A 探索

```
                    ┌─────────────┐
    用户问题 ──────►│  意图路由    │
                    └──────┬──────┘
            ┌──────────────┼──────────────┐
            ▼              ▼              ▼
      【命中模板】     【命中指标】     【未命中】
       路线 C           路线 B          路线 A
     模板槽位填充    语义层受限生成   自由 SQL 探索
     置信度 0.98     置信度 0.90      置信度 0.6
            │              │              │
            │              │        强制标注「未经验证」
            │              │        仅对数据分析师开放
            └──────────────┴──────────────┘
                           ▼
                    结果校验 + 回显口径
```

**降级链**：B 失败 → 转 C 精确模板 → 仍失败 → 反问/转人工。

## 6. 技术选型总表

### 6.1 基础数据平台

| 域 | 首选 | 备选 | 备注 |
|---|---|---|---|
| 数据抽取 | **Apache SeaTunnel** / DataX | Flink CDC（实时） | 医院 HIS 多为 SQL Server/Oracle/Caché，DataX 生态成熟 |
| 调度编排 | **Apache DolphinScheduler** | Airflow / Dagster | 国产、可视化、医院接受度高 |
| 数仓引擎 | **StarRocks / Doris**（MPP，交互式）或 Hive+Spark | ClickHouse | 问数场景要秒级响应，MPP 优于 Hive |
| 湖格式 | Apache Paimon / Iceberg | — | 若走湖仓一体 |
| 转换建模 | **dbt-core** | 自研 SQL 脚本 | 版本化、可评审 |
| 联邦查询 | **Trino** | Dremio | 跨源临时查询 |

### 6.2 治理与元数据

| 域 | 首选 | 备选 |
|---|---|---|
| 元数据/血缘/目录 | **DataHub** | OpenMetadata、Apache Atlas |
| 数据质量 | **Great Expectations** | Soda |
| 主数据/字典 | 自研 MDM 表 + 映射表 | — |

### 6.3 语义层与问数

| 域 | 首选 | 备选 | 说明 |
|---|---|---|---|
| 语义层 | **dbt + MetricFlow** | Cube、自研 YAML | 详见 [03](03-指标字典与语义层建模.md) |
| 问数引擎 | **SuperSonic**（腾讯开源 ChatBI） | DB-GPT、WrenAI、自研 | 详见 [06](06-开源选型与Foundry平替.md) |
| 向量检索 | Milvus / PGVector | Elasticsearch | 指标召回、示例库召回 |
| BI 底座 | **Apache Superset** | Metabase、DataEase | 图表渲染、SQL Lab |

### 6.4 安全与基础设施

| 域 | 选型 |
|---|---|
| 认证 | Keycloak / 院内统一身份认证（CAS、LDAP） |
| 行列级权限 | Apache Ranger + 自研行级过滤 |
| 细粒度授权模型 | **OpenFGA**（ReBAC）或自研 |
| 脱敏 | Apache ShardingSphere 脱敏规则 / 数仓 UDF |
| 审计 | 自研审计表 + 日志平台（ELK / Loki） |
| 模型部署 | vLLM / Xinference（院内 GPU），支持 Qwen / DeepSeek / GLM 等国产模型 |

### 6.5 医疗行业专用

| 组件 | 用途 |
|---|---|
| **OHDSI / OMOP CDM** | 临床数据标准化底座（术语、 visits、conditions、drugs、measurements） |
| **OHDSI ATLAS** | 队列定义、表征（科研场景） |
| **Achilles** | 数据质量画像（先跑一遍看数据长什么样） |
| 医保编码"五统一" | 医保疾病诊断、手术操作、药品、耗材、医疗服务项目编码映射 |

### 7.1 硬性约束

- **数据不出院**：所有组件（含 LLM）私有化部署，禁用任何外网 SaaS API。
- **只读**：问数链路对业务库**零写权限**，物理隔离。
- **信创适配**：预留达梦 / 人大金仓 / OceanBase + 麒麟 OS + 鲲鹏/海光的兼容路线（招标常见要求）。
- **最小 GPU**：7B~14B 模型 + vLLM，单卡 A10/L20（24G）可跑；32B 需 A100 40G 或双卡。

## 9. 与 Palantir Foundry 的能力映射

| Foundry 概念 | 本方案对应 | 开源平替 |
|---|---|---|
| **Ontology（本体）** | 指标语义层 + 主题域模型 | MetricFlow / Cube + **图数据库自建（无成熟开源平替）** |
| Datasets / Pipeline | ODS→DWD→DWS→ADS | dbt + DolphinScheduler |
| Data Lineage | 血缘 | DataHub |
| **Object Explorer / Workshop** | 驾驶舱 + 低代码应用 | Superset + Appsmith/ToolJet |
| **Write-back / Actions** | 行动工单闭环（P4） | 自研 + 工单系统 |
| Permissions / Markings | 行列级权限 + 数据分级 | Ranger + OpenFGA + 自研 |
| Contour / 探索分析 | SQL Lab / 下钻 | Superset |
| AIP / 自然语言 | 问数引擎 | SuperSonic / DB-GPT / 自研 |

**结论**：Foundry 的一体化体验（尤其 Ontology + write-back）**无开源 1:1 平替**；但医院问数场景 80% 的价值集中在「语义层 + 查询 + 可视化 + 权限」，这部分完全可以组合开源实现。详见 [06](06-开源选型与Foundry平替.md)。

## 10. 关键设计决策记录（ADR 摘要）

| # | 决策 | 理由 | 被否决方案 |
|---|---|---|---|
| ADR-01 | 主路线选 Text-to-Metric 而非 Text-to-SQL | 医疗口径复杂，正确性优先于覆盖度 | 直连 Text-to-SQL |
| ADR-02 | 语义层独立成层，指标即代码 + 版本管理 | 口径变更需评审留痕，是可信度基础 | 提示词里写死公式 |
| ADR-03 | 禁止 LLM 推导医疗公式 | 平均住院日/床位使用率等公式必须硬编码 | 让模型自己算 |
| ADR-04 | 时间口径作为指标的一等公民参数 | 入院/出院/结算三口径差异可达 10%+ | 默认用出院日期 |
| ADR-05 | 低置信度强制反问，禁止编造 | 信任成本极高 | 给一个"最可能"的答案 |
| ADR-06 | MPP 数仓（Doris/StarRocks）而非 Hive | 交互式问数要求秒级 | Hive/Spark SQL |
| ADR-07 | 引入 OMOP CDM 作为临床标准化底座 | 避免自研术语映射，复用 OHDSI 生态 | 完全自定义模型 |
| ADR-08 | 模型私有化部署 | 数据不出院、合规一票否决 | 调用公有云 API |
