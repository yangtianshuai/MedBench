# 服务器部署说明

本文说明如何把「医析台」部署到服务器，供多人通过浏览器使用。
分 Windows 与 Linux 两套，步骤可直接照做。

---

## 一、先读这一节：部署前必须确认的三件事

这套程序处理的是**患者数据**。部署前请先确认以下三点 —— 顺序很重要，
**先把访问控制和传输加密做好，再对外开放端口**，而不是反过来。

### 1. 访问认证（必须有）

**Streamlit 自身没有用户认证功能。** 如果只改了监听地址就直接开放，
任何能访问该地址的机器都能打开页面、上传 Excel、看到所有分析结果与报告。

因此必须前置一层认证。本文推荐 **Nginx 反向代理 + Basic Auth** —— 成熟、简单、
不依赖程序本身，且访问日志里能记录是谁在什么时候连的。

### 2. 传输加密（强烈建议）

HTTP 下，**登录密码和患者数据都是明文传输**。医院内网不等于可信网络：终端数量多、
准入难以保证，同网段抓包是可行的。出事时无法自证清白。

**内网做 HTTPS 不需要买域名或证书** —— 用自签证书即可，成本为零：
一条 `openssl` 命令生成证书，Nginx 加两行配置（见第六节）。

唯一代价是医生首次打开会看到「证书不受信任」的提示，点一次「继续访问」；
把这张自签根证书一次性下发到全院电脑后就不再提示。

### 3. 并发容量（决定服务器规格）

Streamlit 每个会话一个线程，但 pandas / scipy / statsmodels 的计算**受 GIL 限制**：
有人在跑重计算时，所有人的页面都会变慢。

| 使用强度 | 单实例可支撑 | 典型操作 |
| -------- | ------------ | -------- |
| 轻 | 15–25 人 | 描述统计、t 检验、Table 1 |
| 中 | 8–12 人 | Logistic / Cox 回归 |
| 重 | **3–5 人** | LASSO + Bootstrap 验证、MICE 多重插补、外部验证 |

**内存**：每人在线占一份数据副本，另有全局共享的读表缓存（已限制为最多 8 份）。
按全院同时在线 50 人、每人 5 万行估算，建议 **16–32 GB**。

> 结论：一台 16 核 / 32 GB 的 Linux 服务器可从容支撑全院日常使用。

## 二、部署架构

```
医生浏览器
    │  HTTP(S)
    ▼
┌─────────────────────────┐
│  Nginx（对全院开放）      │  ← 访问认证 + HTTPS + websocket 转发
└─────────────────────────┘
    │  http://127.0.0.1:8501
    ▼
┌─────────────────────────┐
│  Streamlit（只绑本机）    │  ← 患者数据在这一层，不直接对外
└─────────────────────────┘
```

**关键点：Streamlit 始终只绑定 `127.0.0.1`**，对外只有 Nginx 一个入口。
这样即使认证配置有疏漏，也没有第二条路径能直达应用。

**不要用打包好的 exe 做服务器部署**：它硬编码绑定 `127.0.0.1`、面向单机使用，
而且是 Windows 可执行文件（Linux 跑不了）。服务器部署一律用源码。

**部署或升级前先跑一次冒烟自检**（改完代码、装完依赖后各跑一次最稳妥）：

```bash
python scripts/自检.py            # 全部检查（约 6 分钟）
python scripts/自检.py --fast     # 跳过耗时的分析运行（约 4 分钟）
```

它会启动一个离线的测试实例（不占端口、不碰你的数据），逐个页签与页内分析类型渲染一遍，
并检查「只浏览不点击时报告只应有 1 章」等行为护栏。**全部显示 OK 才算通过**，
有 FAIL 时先别上线。

只需项目中的这几项：

```
medapp/
├── app.py                     # 应用主入口
├── modules/                   # 分析功能模块

```

## 四、Windows 部署

### 4.1 安装 Python 与依赖

1. 安装 **Python 3.11**（[python.org](https://www.python.org/downloads/)），
   安装时务必勾选 **Add python.exe to PATH**。
2. 把上节的文件放到 `C:\medapp`，然后：

```powershell
cd C:\medapp
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

### 4.2 试运行

```powershell
.venv\Scripts\streamlit run app.py `
    --server.address 127.0.0.1 --server.port 8501 --server.headless true
```

本机浏览器打开 `http://127.0.0.1:8501` 确认能用，再按 `Ctrl+C` 停掉。

> `.streamlit/config.toml` 里已经写了这些默认值，实际可以省略参数。
> 但显式写出来更清楚，也便于多实例部署时改端口。

### 4.3 注册为 Windows 服务（开机自启）

推荐用 [NSSM](https://nssm.cc/download)（Windows 服务封装工具）：

```powershell
nssm install MedApp8501 "C:\medapp\.venv\Scripts\streamlit.exe" `
  "run C:\medapp\app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true"
nssm set MedApp8501 AppDirectory C:\medapp
nssm set MedApp8501 Start SERVICE_AUTO_START
nssm start MedApp8501
```

也可以用「任务计划程序」创建开机任务，效果相同。

### 4.4 Nginx for Windows

下载 [nginx.org](https://nginx.org/en/download.html) 的 Windows 版本，解压到 `C:\nginx`，
配置文件见第七节。启动：

```powershell
cd C:\nginx
start nginx
# 重载配置：nginx.exe -s reload
# 停止：    nginx.exe -s quit
```

**Windows 版的限制要说清楚**：不支持 Linux 版的全部特性（如 `ip_hash` 之外的负载均衡策略、
部分 worker 配置），并发能力与稳定性也不如 Linux 版。
**Windows 方案建议同时在线不超过 20 人**，人数更多请用 Linux 做前端。

### 4.5 防火墙

只放行 **80**（或 443）。**不要放行 8501** —— 让 Streamlit 始终只对本机可见。

```powershell
New-NetFirewallRule -DisplayName "MedApp HTTP" -Direction Inbound -Protocol TCP -LocalPort 80 -Action Allow
```

## 五、Linux 部署（推荐）

以下以 Ubuntu 22.04 / Debian 12 为例。

### 5.1 安装依赖

```bash
sudo apt update
sudo apt install -y python3.11 python3.11-venv nginx apache2-utils
```

`apache2-utils` 提供 `htpasswd`，用来生成访问账号。

### 5.2 部署代码

```bash
sudo mkdir -p /opt/medapp
sudo chown $USER /opt/medapp
# 把整个仓库（app.py / modules / requirements.txt / .streamlit）复制到 /opt/medapp

cd /opt/medapp
python3.11 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

### 5.3 专用运行账号

不要用 root 跑服务：

```bash
sudo useradd -r -s /usr/sbin/nologin medapp
sudo chown -R medapp:medapp /opt/medapp
sudo chmod 600 /opt/medapp/ai_server_config.json 2>/dev/null || true
```

### 5.4 systemd 服务

`/etc/systemd/system/medapp.service`：

```ini
[Unit]
Description=MedBench
After=network.target

[Service]
Type=simple
User=medapp
WorkingDirectory=/opt/medapp
ExecStart=/opt/medapp/.venv/bin/streamlit run app.py \
    --server.address 127.0.0.1 --server.port 8501 --server.headless true
Restart=on-failure
RestartSec=3
# 日志（journalctl -u medapp -f 查看）
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now medapp
sudo systemctl status medapp
```

### 5.5 多实例（并发不够时再加）

先用**单实例**跑起来观察并发，确实不够再加实例。多实例时同一会话必须落到同一实例，
否则用户一刷新就会丢失报告与台账。

把 `ExecStart` 里的端口改成占位符，做成模板服务
`/etc/systemd/system/medapp@.service`：

```ini
[Unit]
Description=MedBench (port %i)
After=network.target

[Service]
Type=simple
User=medapp
WorkingDirectory=/opt/medapp
ExecStart=/opt/medapp/.venv/bin/streamlit run app.py \
    --server.address 127.0.0.1 --server.port %i --server.headless true
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now medapp@8501 medapp@8502 medapp@8503
```

Nginx 的 `upstream` 里加上这三个端口即可（见下节）。

> **会话粘滞的取舍**：Nginx 的 `ip_hash` 按客户端 IP 分流。若全院通过同一个出口网关
> 上网，所有请求会被分到同一实例上 —— 负载反而更不均衡。人数多且并发高时，
> 更简单的做法是**开多个入口路径**（`/app1`、`/app2`），让使用者自行选择，
> 而不是依赖自动分流。

## 六、Nginx 配置

### 6.1 生成访问账号

```bash
# 第一个用户用 -c 创建文件，之后追加不加 -c
sudo htpasswd -c /etc/nginx/.htpasswd doctor01
sudo htpasswd /etc/nginx/.htpasswd doctor02
```

给每位使用者单独建账号：访问日志里能追溯到「谁在什么时候连过」。
密码文件权限收紧：`sudo chmod 640 /etc/nginx/.htpasswd && sudo chown root:www-data /etc/nginx/.htpasswd`。

### 6.2 自签证书（推荐）

把 `192.0.2.10` 换成服务器的内网 IP：

```bash
sudo openssl req -x509 -nodes -days 3650 -newkey rsa:2048 \
  -keyout /etc/nginx/medapp.key -out /etc/nginx/medapp.crt \
  -subj "/CN=192.0.2.10" -addext "subjectAltName=IP:192.0.2.10"
```

> 访问地址必须与证书里的 IP 一致，否则浏览器仍会报不安全。

### 6.3 站点配置

`/etc/nginx/sites-available/medapp`（**这一份是 HTTPS 版**）：

```nginx
upstream medapp {
    server 127.0.0.1:8501;
    # 多实例时再启用下面两行，并加上 ip_hash;
    # server 127.0.0.1:8502;
    # server 127.0.0.1:8503;
}

# HTTP 仅用于跳转到 HTTPS；若确定不用 HTTPS，把这段删掉，
# 并把下面 server 块的 listen 改回 80 且去掉两行 ssl_ 配置
server {
    listen 80;
    server_name _;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name _;

    ssl_certificate     /etc/nginx/medapp.crt;
    ssl_certificate_key /etc/nginx/medapp.key;
    ssl_protocols       TLSv1.2 TLSv1.3;

    # 与程序的上传上限（.streamlit/config.toml 的 maxUploadSize）保持一致
    client_max_body_size 200m;

    auth_basic "MedBench";
    auth_basic_user_file /etc/nginx/.htpasswd;

    location / {
        proxy_pass http://medapp;
        proxy_http_version 1.1;

        # websocket —— Streamlit 靠它维持会话，缺了会不断重连
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # AI 生成长文本时单次请求可能很久
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;

        # ★ 必须关闭缓冲：AI 是流式（SSE）返回的，
        # 开启缓冲会让界面长时间不出字，看起来像卡死
        proxy_buffering off;
        proxy_cache off;
    }
}
```

启用：

```bash
sudo ln -s /etc/nginx/sites-available/medapp /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t
sudo systemctl reload nginx
```

### 6.4 不用 HTTPS 时的差异

若确定使用 HTTP，只需改动上面的配置：

1. 删掉整个 80 端口跳转的 `server` 块；
2. 把 443 的 `server` 块改为 `listen 80;`；
3. 删掉两行 `ssl_certificate*` 与 `ssl_protocols`。

其余（认证、websocket、`proxy_buffering off`）**一项都不能少**。

## 七、AI 服务端统一配置

全院使用时不要让每个人各自填服务地址和 Key。程序支持**服务端统一配置**，
配一次之后使用者打开就能用。

### 7.1 用配置文件

把 `ai_server_config.example.json` 复制为 `ai_server_config.json`，
放在以下**任一**位置（程序按顺序查找，找到即用）：

1. 仓库根目录 —— 与 `app.py` 同级
2. 仓库根目录的上一层（整包复制到服务器时）
3. 用户目录 —— Windows: `C:\Users\<用户名>\`，Linux: `~`

内容：

```json
{
  "base_url": "http://your-server:8000/v1",
  "api_key": "",
  "model": "qwen2.5-14b-instruct",
  "timeout": 300,
  "redact": true
}
```

**若要接本地模型**（数据不出内网），`base_url` 填内网地址、`api_key` 留空即可。

### 7.2 用环境变量（容器 / systemd 更方便）

优先级高于配置文件：

```
MEDBENCH_BASE_URL=http://your-server:8000/v1
MEDBENCH_API_KEY=
MEDBENCH_MODEL=qwen2.5-14b-instruct
MEDBENCH_TIMEOUT=300
MEDBENCH_REDACT=true
```

systemd 里加：

```ini
Environment="MEDBENCH_BASE_URL=http://your-server:8000/v1"
Environment="MEDBENCH_MODEL=qwen2.5-14b-instruct"
```

### 7.3 生效后的表现

- 侧边栏显示「**AI 由服务端统一配置**」，不再要求填写
- 使用者仍可勾选「临时覆盖服务端配置」自行填写，**仅影响他自己的会话**
- 配置改动后需要重启服务（程序会缓存这份配置）

**注意**：`api_key` 在文件里是明文。Linux 下：

```bash
sudo chmod 600 /opt/medapp/ai_server_config.json
sudo chown medapp:medapp /opt/medapp/ai_server_config.json
```

## 八、升级与备份

### 升级

```bash
sudo systemctl stop medapp
# 覆盖 app.py / modules 与 requirements.txt
.venv/bin/pip install -r requirements.txt
sudo systemctl start medapp
```

依赖没变时可以跳过 `pip install`。

### 需要备份的

| 内容 | 位置 | 说明 |
| ---- | ---- | ---- |
| AI 配置 | `ai_server_config.json` | 含 Key |
| 访问账号 | `/etc/nginx/.htpasswd` | |
| 证书 | `/etc/nginx/medapp.*` | 自签证书有效期 10 年 |
| 用户项目文件 | 由用户自行导出（`.mda`） | **服务器上不保存** |

**服务器不保存任何患者数据**：上传的文件只存在于内存，会话断开即释放；
报告由用户自行下载。这是设计上的隐私优点，但也意味着**刷新页面会丢失会话状态** ——
需要保留的分析请用程序内的「项目保存」导出 `.mda` 文件。

## 九、排错清单

| 现象 | 原因与处理 |
| ---- | ---------- |
| 浏览器打不开页面 | 防火墙是否放行 80/443；`sudo systemctl status nginx`；`nginx -t` 看配置语法 |
| 页面打开但一直「正在连接」 | websocket 没转发 —— 检查 `proxy_set_header Upgrade/Connection` 两行 |
| 要求登录但密码总是错 | `htpasswd` 文件路径与权限；`chown root:www-data` 后需 `reload nginx` |
| **AI 输出半天不出字** | **`proxy_buffering off` 没加**（最常见）；或 `proxy_read_timeout` 太小 |
| 上传大文件失败 | `client_max_body_size` 小于文件；也要看 `.streamlit/config.toml` 的 `maxUploadSize` |
| 刷新后报告和台账没了 | 正常现象：状态在内存里。已有多实例且未做会话粘滞时更明显 |
| 多人同时用很卡 | 受 GIL 限制。加实例（见 5.5），并提醒重计算错峰 |
| 改了 AI 配置不生效 | 程序缓存了配置，需要 `systemctl restart medapp` |
| 界面提示「未配置 AI」 | 服务端配置文件路径不对，或 JSON 格式错误；也可用环境变量 |
| 导出 Word 报错 | 检查 `python-docx` 是否装上：`.venv/bin/pip install python-docx` |

查看日志：

```bash
sudo journalctl -u medapp -n 100 --no-pager     # 应用日志
sudo tail -f /var/log/nginx/error.log           # Nginx 错误
sudo tail -f /var/log/nginx/access.log          # 访问记录（含用户名）
```

## 十、仅供本机使用（不做服务器）

如果只是自己一台机器用，**不用做上面任何配置**：

- 直接用打包好的 `医析台.exe`，双击即用，只监听 `127.0.0.1`，
  局域网内其他机器访问不到
- 或源码方式：

```bash
streamlit run app.py
```

`.streamlit/config.toml` 的默认值就是「只绑本机 + 关闭使用统计」，
这正是单机使用想要的状态。
