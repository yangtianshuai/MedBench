# 02 · 数据模型设计

## 1. 分层规范

| 层 | 名称 | 职责 | 是否暴露给问数 | 命名前缀 |
|---|---|---|---|---|
| ODS | 原始数据层 | 业务库镜像，只做抽取与快照，不做清洗 | ❌ | `ods_<源系统>_<表名>` |
| DWD | 明细数据层 | 清洗、标准化、主数据映射、一致性维度 | ⚠️ 仅数据分析师 | `dwd_fact_*` / `dwd_dim_*` |
| DWS | 汇总数据层 | 主题宽表、轻度聚合 | ✅ 受控 | `dws_<主题>_*` |
| ADS | 应用数据层 | 指标结果表、驾驶舱宽表 | ✅ | `ads_<场景>_*` |
| DIM | 公共维度层 | 一致性维度（科室/人员/时间/诊断/药品） | ✅ | `dim_*` |
| TMP | 临时层 | 中间过程 | ❌ | `tmp_*` |

> **问数引擎只面向 DWS/ADS/DIM，绝不面向 ODS。** 这一条能挡掉 80% 的口径事故。

## 3. 核心 DDL 示例

### 3.1 DWD：门诊就诊事实表

```sql
CREATE TABLE dwd_fact_outpatient_visit (
    visit_sk            BIGINT       COMMENT '代理键',
    -- 业务主键
    visit_id            STRING       COMMENT '就诊唯一号（院内）',
    patient_id          STRING       COMMENT '患者主索引 ID（已映射）',
    -- ★ 三个时间口径，全部保留
    reg_date            DATE         COMMENT '挂号日期',
    visit_date          DATE         COMMENT '就诊日期',
    settle_date         DATE         COMMENT '结算/收费日期',
    visit_month         STRING       COMMENT '就诊月份 YYYY-MM（预计算分区）',
    -- ★ 科室三口径，全部保留
    order_dept_code     STRING       COMMENT '开单科室编码',
    exec_dept_code      STRING       COMMENT '执行科室编码',
    belong_dept_code    STRING       COMMENT '患者归属/接诊科室编码',
    doctor_id           STRING       COMMENT '接诊医师 ID',
    -- 维度
    visit_type_code     STRING       COMMENT '就诊类型：普通/专家/急诊/便民/互联网',
    patient_source_code STRING       COMMENT '患者来源：本地/外地/转诊',
    pay_type_code       STRING       COMMENT '费别：自费/医保/商保/公费',
    -- 度量
    is_valid_visit      TINYINT      COMMENT '是否有效就诊（已退号=0，已就诊=1）',
    is_first_visit      TINYINT      COMMENT '是否初诊',
    total_fee           DECIMAL(18,2) COMMENT '总费用',
    drug_fee            DECIMAL(18,2) COMMENT '药品费用',
    herb_fee            DECIMAL(18,2) COMMENT '中草药费用',
    material_fee        DECIMAL(18,2) COMMENT '卫生材料费用',
    exam_lab_fee        DECIMAL(18,2) COMMENT '检查化验费用',
    treat_fee           DECIMAL(18,2) COMMENT '治疗费用',
    -- 治理字段
    data_maturity       STRING       COMMENT 'settled=已结算落定 / provisional=未落定',
    etl_time            TIMESTAMP,
    source_system       STRING
)
COMMENT '门诊就诊事实表（粒度：一次就诊）'
PARTITIONED BY (visit_month)
```

### 3.2 DWD：住院出院事实表

```sql
CREATE TABLE dwd_fact_inpatient_discharge (
    stay_sk              BIGINT,
    visit_id             STRING       COMMENT '住院就诊号',
    patient_id           STRING,
    -- ★ 时间三口径
    admit_date           DATE         COMMENT '入院日期',
    discharge_date       DATE         COMMENT '出院日期',
    settle_date          DATE         COMMENT '结算日期',
    admit_month          STRING,
    discharge_month      STRING,
    settle_month         STRING,
    -- ★ 科室三口径
    admit_dept_code      STRING       COMMENT '入院科室',
    discharge_dept_code  STRING       COMMENT '出院科室（最常用）',
    belong_dept_code     STRING       COMMENT '患者归属科室/病区',
    ward_code            STRING       COMMENT '病区',
    attending_doctor_id  STRING       COMMENT '主管医师',
    -- 维度
    admit_type_code      STRING       COMMENT '入院途径：门诊/急诊/转院',
    discharge_type_code  STRING       COMMENT '离院方式：医嘱离院/转院/死亡/非医嘱离院',
    pay_type_code        STRING,
    -- 度量
    los_days             DECIMAL(10,2) COMMENT '住院天数（出院日-入院日）',
    occupy_bed_days      DECIMAL(10,2) COMMENT '占用床日数（跨科累加口径）',
    total_fee            DECIMAL(18,2),
    drug_fee             DECIMAL(18,2),
    material_fee         DECIMAL(18,2),
    -- 质控标记
    is_unplanned_readmit_31d TINYINT  COMMENT '31 日内非计划再入院',
    is_death_in_hospital     TINYINT,
    -- 治理
    data_maturity        STRING,
    etl_time             TIMESTAMP
)
COMMENT '住院出院事实表（粒度：一次出院）'
```

> ⚠️ **注意**：`los_days`（出院日-入院日）与 `occupy_bed_days`（占用床日数）**不是一回事**。跨科转科患者按出院科室统计住院日时，必须用 `occupy_bed_days` 按科室分摊，否则科室平均住院日会失真。

### 3.3 公共维度：科室

```sql
CREATE TABLE dim_department (
    dept_code        STRING  COMMENT '科室编码（院内唯一）',
    dept_name        STRING  COMMENT '科室标准名称',
    dept_alias       STRING  COMMENT '别名（用于问数同义词召回）',
    dept_type        STRING  COMMENT '临床/医技/行政/后勤',
    is_clinical      TINYINT COMMENT '是否临床科室',
    parent_dept_code STRING  COMMENT '上级科室（科室组）',
    campus_code      STRING  COMMENT '院区编码（多院区必填）',
    campus_name      STRING,
    -- 外部映射
    std_dept_code    STRING  COMMENT '国家/省标准科室编码',
    -- 缓慢变化维
    valid_from       DATE,
    valid_to         DATE,
    is_current       TINYINT
)
COMMENT '科室一致性维度（SCD Type 2）'
```

> 科室维度**必须做 SCD Type 2**。医院科室合并/拆分频繁，否则历史数据会串科。这是最常见的历史数据错误来源。

### 3.4 主数据映射表（字典映射通用结构）

```sql
CREATE TABLE dim_mapping_dict (
    dict_type        STRING  COMMENT '字典类型：ICD10/ICD9CM3/ATC/DEPT/PAY_TYPE/医保五统一',
    src_system       STRING  COMMENT '来源系统：HIS/EMR/医保/物资',
    src_code         STRING  COMMENT '源编码',
    src_name         STRING  COMMENT '源名称',
    std_code         STRING  COMMENT '标准编码',
    std_name         STRING  COMMENT '标准名称',
    map_confidence   STRING  COMMENT 'exact/fuzzy/manual',
    mapped_by        STRING  COMMENT 'auto/manual',
    verified_by      STRING  COMMENT '人工审核人',
    valid_from       DATE,
    valid_to         DATE
)
COMMENT '主数据字典映射表'
```

**映射覆盖率是数据质量的一号指标**，建议做成看板：

```sql
SELECT dict_type,
       COUNT(*)                                          AS total,
       SUM(CASE WHEN std_code IS NULL THEN 1 ELSE 0 END) AS unmapped,
       ROUND(SUM(CASE WHEN std_code IS NULL THEN 1 ELSE 0 END) * 100.0 / COUNT(*), 2) AS unmapped_rate
FROM dim_mapping_dict
GROUP BY dict_type
ORDER BY unmapped_rate DESC;
```

### 3.5 ADS：指标结果表（预聚合）

```sql
CREATE TABLE ads_metric_daily (
    stat_date        DATE          COMMENT '统计日期',
    date_basis       STRING        COMMENT '★ admit/discharge/settle（时间口径）',
    metric_code      STRING        COMMENT '指标编码（关联语义层）',
    dept_code        STRING        COMMENT '科室（-1=全院）',
    campus_code      STRING,
    dim_combo        STRING        COMMENT '其他维度组合（JSON）',
    metric_value     DECIMAL(20,4),
    metric_value_mom  DECIMAL(20,4) COMMENT '环比',
    metric_value_yoy  DECIMAL(20,4) COMMENT '同比',
    data_maturity    STRING,
    etl_time         TIMESTAMP
)
COMMENT '指标日粒度结果表（预聚合，问数主表）'
PARTITIONED BY (stat_date)
```

**预聚合是性能与成本的关键**：80% 的问数命中 `ads_metric_daily`，毫秒级返回；复杂下钻才走 DWS 实时计算。

## 4. 三个"必须显式建模"的口径陷阱

### 4.1 时间口径（date_basis）

| date_basis | 含义 | 适用场景 |
|---|---|---|
| `admit` | 入院日期 | 住院流量、在院分析 |
| `discharge` | 出院日期 | **出院人次、平均住院日、住院收入的默认口径** |
| `settle` | 结算/财务入账日期 | **财务、医保、DRG 盈亏的默认口径** |

**实现要点**：
1. DWD 表三个日期字段全留，不做取舍。
2. 语义层每个指标**必须声明 `default_date_basis`**，且允许查询时覆盖。
3. 前端回显："本指标按【出院日期】统计"。
4. 财务类指标必须展示 `data_maturity`，未落定的数据加灰色标注。

### 4.2 科室归属口径（dept_basis）

| dept_basis | 含义 | 典型使用方 |
|---|---|---|
| `order` | 开单科室 | 收入归属、工作量考核 |
| `exec` | 执行科室 | 医技科室工作量、设备利用率 |
| `belong` | 患者归属科室（出院科室/病区） | **医务质控、平均住院日、DRG** |

**实现要点**：同一指标的三种科室口径要能一键切换，并在图表上标明。科室间数据打架 90% 源于此。

### 4.3 人次 vs 人数（dedup）

| 模式 | 定义 |
|---|---|
| `visits` | 人次：不去重，一次就诊/一次出院算 1 |
| `patients` | 人数：按 `patient_id` 去重 |

必须在语义层声明，并在界面显示"人次/人数"。

## 5. 数据成熟度标记（data_maturity）

| 值 | 含义 | 前端表现 |
|---|---|---|
| `settled` | 已结算落定，不再变化 | 正常黑色 |
| `provisional` | 未落定（如当日数据、未结算费用） | 灰色 + "未结算"角标 |
| `restated` | 已被回刷修正 | 提示"本数据已修正" |

**典型场景**：本月 3 日看"上月收入"必然偏低（部分病例未结算）。不标注会让用户误判为"收入暴跌"。

## 6. 与 OMOP CDM 的关系

### 6.1 建议策略：双轨制

```
                 DWD（运营/管理口径）
                ╱
   业务原始数据 ── 标准化/主数据映射
                ╲
                 OMOP CDM（临床/科研口径）
```

| 用途 | 走哪条轨 |
|---|---|
| 运营、财务、医保、质控问数 | **DWD/DWS/ADS** |
| 科研队列、专病库、临床表征、多中心研究 | **OMOP CDM + ATLAS** |

### 6.2 OMOP 核心表（用于科研问数）

| 表 | 内容 |
|---|---|
| `person` | 患者基本信息 |
| `visit_occurrence` | 就诊（门诊/住院/急诊） |
| `condition_occurrence` | 诊断（映射至 SNOMED/ICD） |
| `procedure_occurrence` | 操作/手术 |
| `drug_exposure` | 用药 |
| `measurement` | 检验 |
| `observation` | 观察 |
| `death` | 死亡 |

### 6.3 落地建议

1. **先跑 Achilles**：生成全院数据质量画像，暴露映射缺失、异常分布。这一步 2 周可完成，价值极高。
2. 术语映射复用 OHDSI 官方 vocabulary（需下载 + 定期更新），ICD-10 → SNOMED 已有官方映射。
3. 不要试图用 OMOP 替代运营管理口径——它的粒度与财务口径不对齐，硬套会导致数字对不上 HIS 报表。

## 7. 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 表 | `<层>_<fact|dim|ads>_<主题>_<业务含义>` | `dwd_fact_outpatient_visit` |
| 字段 | 蛇形小写 | `discharge_date` |
| 编码字段 | 统一 `_code` 后缀 | `dept_code` |
| 名称字段 | 统一 `_name` 后缀 | `dept_name` |
| 金额 | `DECIMAL(18,2)` + `_fee` 后缀 | `total_fee` |
| 比率 | `DECIMAL(10,4)` + `_rate` 后缀 | `drug_rate` |
| 数量 | `_cnt` 后缀 | `visit_cnt` |
| 日期 | `_date` 后缀 | `admit_date` |
| 标记 | `is_` 前缀 + TINYINT | `is_valid_visit` |
| 指标编码 | `<域>_<对象>_<度量>` | `op_visit_cnt` |

## 8. 数据质量规则（Great Expectations 建议内置）

| 规则 | 适用 | 严重级 |
|---|---|---|
| 主键唯一 | 所有事实表 | 阻断 |
| 外键完整性（dept_code ∈ dim_department） | 事实表 | 阻断 |
| 日期合理性（admit_date ≤ discharge_date） | 住院事实 | 阻断 |
| 金额非负或允许负（退费） | 费用字段 | 告警 |
| 映射覆盖率 ≥ 98% | 字典映射 | 告警 |
| 日增量波动 ≤ ±50% | 事实表 | 告警（人工确认） |
| 空值率 | 关键维度 | 告警 |
| 科室不应为 NULL | 所有事实表 | 阻断 |

> **日增量波动告警**非常有用：能第一时间发现 HIS 接口变更、抽取中断、字典失效。

## 9. 建模型 checklist

- [ ] ODS 只读镜像，保留历史快照（至少 T-1 全量 + 增量日志）
- [ ] 事实表三个时间字段（admit/discharge/settle）齐全
- [ ] 事实表科室字段齐全（门诊：order/exec/belong；住院：admit/discharge/belong）
- [ ] 科室维度 SCD Type 2
- [ ] 多院区 `campus_code` 贯穿所有事实与维度
- [ ] 字典映射表有审核人与有效期
- [ ] `data_maturity` 标记到位
- [ ] 预聚合 ADS 表按 stat_date + date_basis + dept 三维建索引
- [ ] 所有金额统一 DECIMAL(18,2)，禁止 FLOAT
